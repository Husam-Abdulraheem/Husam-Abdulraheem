## Engineering Approach

I generally approach software development around a few principles:

**Clarity over cleverness**
Code should be understandable before it is optimized for abstraction.

**Separation of concerns**
Business logic, infrastructure, and presentation should have clear responsibilities.

**Design for change**
Good architecture should make future requirements easier to implement rather than harder.

**Validate assumptions**
I prefer testing ideas through implementation, profiling, debugging, and real usage instead of relying only on theoretical design.

**AI as a development tool**
I use AI-assisted tools such as coding agents and IDE assistants to accelerate implementation, exploration, refactoring, and debugging — while reviewing and validating the resulting code myself.
